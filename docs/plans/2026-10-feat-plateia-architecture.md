# Implementation Plan: Plateia (fastTicket) — Domains, Folder Architecture, Phasing

> Sources: the Plateia ticketing PRD and the Plateia architecture document (kept outside the repo, not versioned).
> Language: code, identifiers and table names in English. Documentation in pt-BR and English.
> Decision record: [ADR 001](../adr/001-monolito-modular-postgres-fonte-unica.md).

## Overview

Plateia is a seat-reserved ticketing API: hold seats for 10 minutes, pay with an idempotent checkout, never sell a seat twice. Architecture is a **modular monolith** (single Gradle module, base package `com.fastticket`), one image running as `api` or `worker` profile. Postgres is the single source of truth and the only clock; Redis is used only from phase 5.

## Decisions (confirmed)

- Base package stays `com.fastticket`; single Gradle module; package-by-module with light layers (`api`, `application`, `domain`, `infra`).
- Payment gateway mock: **WireMock** with chaos (latency, timeout %, duplicate callback %), as a separate container in docker-compose.
- Remove the `org.graalvm.buildtools.native` plugin.
- Code and names in English; docs in pt-BR and English.

## 1. Domains

| Module | Owns | Depends on |
|---|---|---|
| `catalog` | event, sector, seat, seatmap (read) | — |
| `pricing` | lot, half-price quota (`half_held/half_sold`), current-lot resolution | `catalog` |
| `inventory` | seat_allocation, sector_inventory, buyer_event, hold, hold_item, `SeatAllocator` | `catalog`, `pricing` |
| `payments` | `PaymentGateway` port, adapters (WireMock/real), webhook contract | — |
| `checkout` | payment, order, refund, outbox, cancellation | `inventory`, `payments`, `shared/idempotency` |
| `queue` | virtual queue (Redis), admission, JWT access token | — |
| `realtime` | SSE, pub/sub, seatmap cache and version | listens to events from `inventory`, `checkout` |
| `jobs` | expiration sweeper, reconciliation, outbox dispatch, queue admission | public APIs of other modules |

Rules:
- Idempotency table lives in `shared/idempotency` (used by holds and checkout).
- Hold + allocation stay in `inventory`: one transaction must touch seat, lot, half quota and `buyer_event`.
- `pricing` exposes operations that join the caller's transaction (`reserveLot`, `reserveHalf`, `releaseLot`, `commitLot`).
- `realtime` is triggered by application events after commit (`@TransactionalEventListener(AFTER_COMMIT)`); business modules never know Redis.
- Module dependency rules enforced by an ArchUnit test (from phase 0).

## 3. Phases

Each phase starts only when the previous one passes its gate.

| Phase | Deliverable | Gate |
|---|---|---|
| **0. Foundation** | Deps (jdbc, micrometer-prometheus, ArchUnit), remove GraalVM plugin, docker-compose (api + postgres + wiremock), Liquibase base, `DbClock`, profiles, `InvariantChecker` | App boots in compose; `InvariantChecker` runs on empty DB; ArchUnit green |
| **1. Core** | Full schema with constraints; event/sector/seat registration; seatmap; hold with conditional insert + idempotency; checkout with outbox + webhook | Simple purchase end to end; repeated `Idempotency-Key` returns same response; 5 invariants green after tests |
| **2. Concurrency** | `SeatAllocator` with 3 strategies (conditional, pessimistic `NOWAIT`, optimistic) + benchmark | 100 threads on one seat → 1 winner; 0 duplicates in all 3; comparison table (conflict rate, p99); default chosen via ADR |
| **3. Resilience** | WireMock chaos (`LATENCY_MS`, `TIMEOUT_PCT`, `DUP_CALLBACK_PCT`), reconciliation, expiration job + lazy expiration, cancellation + refund | Chaos test with 0 orphan payments; expired hold back on map < 30 s; duplicate webhook is a no-op; late approval honored or refunded |
| **4. Pricing and seat rules** | GA lots, half price (40%), isolated-seat rule, 6-per-CPF limit | One test per PRD rule; invariants 2, 3, 4 under concurrent load |
| **5. Scale** | Redis: virtual queue, SSE pub/sub, seatmap cache with `version`, CPF rate limit; separate `worker` container; metrics + Grafana | k6 5k VUs with queue on: p99 `POST /holds` < 300 ms; SSE delay < 2 s; 0 duplicates, 0 orphans |

Phase 1 ships the whole schema with constraints (including `lot`, `sector_inventory`, `refund`) because it is the costliest thing to change later; lot/half *business rules* only arrive in phase 4.

## Security Considerations

- **Sensitive areas:** PII (CPF), payments, external API (gateway webhook), user input, database migrations.
- **Mitigations:**
  - [ ] Never log full CPF (mask) or store it unprotected beyond what the model needs
  - [ ] Authenticate webhook callbacks (shared secret/signature) even against the mock
  - [ ] Validate and bound all inputs (qty, ids); parameterized queries only
  - [ ] Queue JWT secret from environment, never hardcoded
  - [ ] Migrations: forward-only, reviewed for locks (see safe-migrations)

## Considerations

- **Risk:** scope creep before phase 2 is solid; Spring Boot 4.1.1 compatibility of Redis/Micrometer starters (check before phase 5); local load numbers compare strategies, not production.
- **Alternative:** multi-module Gradle per domain (rejected: unnecessary at this size).
- **Out of scope:** real gateway, resale/transfer, gate access/QR, full frontend, "best seats" feature (removed from architecture).

## Delivery Workflow

> Applies to every phase. Each phase is a separate cycle: plan → implement → review loop → document → PR.

1. [ ] **Plan** — `/craft-core:plan` for the phase (this document is the master plan; each phase gets its own detailed plan)
2. [ ] **Create branch** `feat/<phase-slug>` (e.g. `feat/foundation`, `feat/core-hold-checkout`)
3. [ ] **Implement** — `/craft-core:implement` executes the phase plan
4. [ ] **Review loop** — `/craft-core:review`, fix findings with `/craft-core:implement`, repeat until confident (no open blocking findings, `./gradlew build` green)
5. [ ] **Document** — `/craft-core:document` generates what was done and how (per domain, in `docs/`), pt-BR and English
6. [ ] **Commit** — Conventional Commits, **no `Co-Authored-By` and no AI attribution**
7. [ ] **Open pull request in draft** — `gh pr create --draft` (add `--label "migration"` on phases with schema changes: phase 1 onward)
